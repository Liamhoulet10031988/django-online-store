# Интернет-магазин на Django

## Описание

Учебный интернет-магазин на Django, который развивается в рамках курса
Python-разработки. Проект хранит товары, категории, контактные данные и статьи
блога в PostgreSQL.

Каталог и блог работают через классовые контроллеры Django. Для статей
реализованы создание, просмотр, изменение и удаление, фильтрация по признаку
публикации и счетчик просмотров.

## Установка

Установить зависимости:

```bash
poetry install
```

Создать PostgreSQL-базу `django_online_store`.

Создать `.env` по примеру `.env.example` и указать свои данные PostgreSQL и
SMTP. Настоящие пароли не должны попадать в Git.

Применить миграции:

```bash
poetry run python manage.py migrate
```

При необходимости загрузить товары и категории:

```bash
poetry run python manage.py load_products
```

Создать учебные группы и назначить им права:

```bash
poetry run python manage.py create_groups
```

## Кеширование и бизнес-логика

Для кеша проект использует Redis. Зависимость Python уже описана в
`pyproject.toml`; после клонирования установите её общей командой:

```bash
poetry install
```

Добавьте в локальный `.env` адрес Redis (в `.env.example` уже есть безопасный
пример):

```text
REDIS_URL=redis://127.0.0.1:6379/1
```

Перед запуском Django должен работать Redis-сервер на порту `6379`. Затем
откройте две страницы:

```text
http://127.0.0.1:8000/
http://127.0.0.1:8000/products/1/
```

В отдельном терминале проверьте, что Redis отвечает и содержит ключи кеша:

```bash
redis-cli ping
redis-cli -n 1 --scan
```

Команда `PING` должна вернуть `PONG`. Список каталога сохраняется
низкоуровневым кешем на 15 минут, а страница товара — кешем страницы на тот же
срок. Страница товаров выбранной категории доступна по адресу
`/categories/<id>/products/`.


## ViewSet и Generic API

В проект добавлен Django REST Framework и приложение `materials` для учебных
материалов. Модель `Course` хранит название, превью и описание курса. Модель
`Lesson` связана с курсом через `ForeignKey` и хранит название, описание, превью
и ссылку на видео.

Полный CRUD курсов реализован через `ModelViewSet` и `DefaultRouter`. CRUD уроков
разделён между `ListCreateAPIView` и `RetrieveUpdateDestroyAPIView`. Для задания со
звёздочкой добавлен API-эндпоинт просмотра и изменения профиля любого
пользователя. Существующая модель `User` наследует `AbstractUser`, который в Django
построен на `AbstractBaseUser`; вход по-прежнему выполняется по email. В профиль добавлено
поле города.

Основные API-адреса:

```text
http://127.0.0.1:8000/api/courses/
http://127.0.0.1:8000/api/courses/<id>/
http://127.0.0.1:8000/api/lessons/
http://127.0.0.1:8000/api/lessons/<id>/
http://127.0.0.1:8000/api/users/
http://127.0.0.1:8000/api/users/<id>/
http://127.0.0.1:8000/api/payments/
http://127.0.0.1:8000/api/subscriptions/
http://127.0.0.1:8000/api/token/
http://127.0.0.1:8000/api/token/refresh/
```

Все API-адреса, кроме регистрации и получения токенов, доступны только с
JWT-токеном. Обычные пользователи видят и изменяют только свои курсы и уроки.
Модераторы могут просматривать и изменять любые курсы и уроки, но не могут
создавать или удалять их.

Загрузить группу модераторов:

```bash
poetry run python manage.py loaddata moderators
```

Для авторизованного запроса передайте access-токен в заголовке:

```text
Authorization: Bearer <access-токен>
```

## Проверка данных, подписки и пагинация API

Ссылка на видео урока проходит дополнительную проверку: разрешены только URL
домена `youtube.com`. Некорректный адрес не сохраняется, а API возвращает
понятное сообщение об ошибке.

Списки курсов и уроков разделены на страницы. По умолчанию возвращается пять
объектов, а параметр `page_size` позволяет запросить до двадцати:

```text
GET /api/courses/?page=1&page_size=3
GET /api/lessons/?page=2&page_size=5
```

Авторизованный пользователь может добавить или удалить подписку на курс одним
POST-запросом:

```http
POST /api/subscriptions/

{
  "course_id": 1
}
```

Если подписки нет, она создаётся. Повторный запрос удаляет её. Сериализатор
курса возвращает поле `is_subscribed` со значением `true` или `false` для
текущего пользователя.

API проверяется тестами DRF на основе `APITestCase`. Отчёт покрытия сохраняется
в `coverage.txt`.

## Документация API и оплата курсов

OpenAPI-схема проекта формируется с помощью `drf-spectacular`. Swagger UI и
Redoc доступны без JWT, но указанные в них защищённые операции по-прежнему
требуют access-токен:

```text
http://127.0.0.1:8000/api/schema/
http://127.0.0.1:8000/api/docs/
http://127.0.0.1:8000/api/redoc/
```

Для Stripe используется только серверный тестовый ключ из локального `.env`.
Добавьте свои тестовые настройки по образцу `.env.example`:

```text
STRIPE_SECRET_KEY=sk_test_your_key
STRIPE_CURRENCY=rub
STRIPE_SUCCESS_URL=http://127.0.0.1:8000/api/payments/?payment=success
STRIPE_CANCEL_URL=http://127.0.0.1:8000/api/payments/?payment=cancelled
```

Создание оплаты курса:

```http
POST /api/payments/create/
Authorization: Bearer <access-токен>
Content-Type: application/json

{
  "paid_course": 1,
  "amount": "1500.00"
}
```

Приложение последовательно создаёт в Stripe продукт, цену и Checkout Session.
Цена передаётся целым числом копеек. В локальном платеже сохраняются ID всех
трёх объектов, ссылка на оплату и статусы Stripe.

Получить актуальный статус своей оплаты и синхронизировать его с базой:

```http
GET /api/payments/<id>/status/
Authorization: Bearer <access-токен>
```

Тесты подменяют Stripe SDK и не выполняют внешние сетевые запросы.

## Фоновые и периодические задачи

Celery использует Redis как брокер сообщений. После успешного обновления
курса подписчикам асинхронно отправляется письмо. Повторная рассылка ставится
в очередь только тогда, когда с предыдущего обновления курса прошло не менее
четырёх часов.

Celery beat раз в сутки запускает пакетную блокировку активных пользователей,
которые не входили в систему более 30 дней.

Для запуска компонентов в отдельных терминалах:

```powershell
poetry run python manage.py runserver
poetry run celery -A config worker -l INFO -P eventlet
poetry run celery -A config beat -l INFO
```
